# Application Fit Analyzer

**[Try it live →](https://application-fit-analyzer.streamlit.app)**

**Should I apply for this job, and where am I weak?**

Job seekers can read a job description perfectly well. What's hard is judging honestly whether they're a credible candidate — and if not, exactly where the shortfall is. That comparison is tedious to do properly, so almost nobody does it.

Paste a job description, add your CV, and get a requirement-by-requirement assessment of how well the two match.

## The design constraint that matters

**Every claim this tool makes is backed by a verbatim quote from the CV.** No supporting quote, no claim.

If a requirement is marked as evidenced, the exact line from the CV that supports it is shown alongside. Quotes are verified in Python against the source text — if a quote can't be found, the claim is automatically downgraded to "not evidenced" rather than trusted.

This exists because the failure mode of an AI fit checker is telling people what they want to hear. A tool that infers "leadership experience" from a senior job title, or reasons from adjacent experience to a match that isn't there, sends someone into an interview unprepared for the question they can't answer. Structural verification is more reliable than asking a model nicely.

The same principle applies to the score: it's computed in Python from the verdicts, never generated by the model. Requirements met count as one, partially met count as half. The user can count the rows and check the arithmetic.

## What it reports

- **A must-have score and a nice-to-have score**, kept separate — a strong candidate missing a few nice-to-haves is a completely different situation from a weak candidate missing core requirements
- **Every requirement**, grouped by verdict, with gaps shown first because that's what needs action
- **Evidenced** — with the quote from the CV
- **Partially evidenced** — with the shortfall named ("5 years against the 8 asked for")
- **Not evidenced** — nothing in the CV supports it. The statement is about the document, not the person; a screener only sees the document too
- **Keywords absent from the CV** that an applicant tracking system may screen on
- **Strengths the job description didn't ask for** — interview angles, not gaps
- **About the role** — seniority signals, estimated salary band, and language in the posting worth questioning

## Worked example

A pastry chef CV tested against a SAP SuccessFactors architect role scores 8% on must-haves, with the recommendation: *"This candidate is not a fit… This application should not be advanced."*

Out of twenty-one requirements it claims exactly one match — "Led kitchen teams of up to 8 people" against "Experience in leading and mentoring teams." That requirement was written without domain qualification, and the CV genuinely evidences it. A human reviewer would make the same call.

The tool is willing to say no. That's what makes a yes worth reading.

## Privacy

CVs are processed entirely in memory. Nothing is written to disk, logged, or retained after the analysis renders.

## Running it yourself

The hosted version is capped at three analyses per session, since it runs on my own API key. To use it without limits:

**1. Clone and create a virtual environment**

```bash
git clone https://github.com/deanmykagpoon/application-fit-analyzer.git
cd application-fit-analyzer
python3 -m venv venv
source venv/bin/activate
```

**2. Install dependencies**

```bash
pip3 install -r requirements.txt
```

**3. Add your Anthropic API key**

Create a `.env` file in the project root:

```
ANTHROPIC_API_KEY=your-api-key-here
```

**4. Run**

```bash
streamlit run app.py
```

## How it works

```
Job description ──┐
                  ├─→ single Claude call ─→ structured JSON ─→ validation ─→ report
CV (PDF/DOCX) ────┘
```

| File | Purpose |
|---|---|
| `app.py` | Streamlit interface and report rendering |
| `cv_reader.py` | In-memory text extraction from PDF and Word documents |
| `match_engine.py` | Prompt construction, API call, validation, and scoring |

Three validation layers run on every response: a schema check that fails closed, a substring check verifying each quote against the CV, and a downgrade step that corrects unverifiable claims rather than discarding the whole report.

The job description and CV are passed inside delimited blocks with an explicit instruction that their contents are material to analyse, never instructions to follow.
